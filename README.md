# Kioku（記憶）

**話したことを、そのまま残す。** — リアルタイム文字起こしと複数メモを、ひとつの画面で扱う個人用アプリです。

提案書『リアルタイム文字起こし・複数メモ管理アプリ』のMVPを、**Androidのブラウザ（Chrome）で動くPWA**として実装したものです。
インストール不要で開けて、ホーム画面に追加すればアプリのように使えます。記録データは端末内だけに保存されます。

## できること

| 領域 | 実装した機能 |
| --- | --- |
| セッション | 新規作成（タイトル・用途・参加者・タグ）、下書き保存、一覧、詳細、追記 |
| 音声入力 | 録音の開始・一時停止・再開・終了、音声の端末内保存、書き出し |
| 文字起こし | ストリーミング表示（途中結果／確定結果を分離）、タイムスタンプ、**文字入力での修正・訂正**、手入力での追加 |
| 複数メモ | 気づき／TODO／確認事項／要約／引用の5種別、色分け、発言位置への紐づけ、編集・削除 |
| 検索・整理 | 全文検索（本文・メモ・タグ横断のAND検索）、タグ・日付フィルタ、4種の並び替え、セッション内検索とハイライト |
| 出力 | テキスト／Markdown／CSV／JSON／音声のダウンロード、Androidの共有シート |
| バックアップ | 全件JSONエクスポート、インポート（IDが重なっても上書きしない） |
| 設定 | 認識言語、自動再開、音声保存の有無、画面の消灯防止、保存期間（自動削除）、全データ削除、端末の対応状況表示 |

### 記録中の画面

- 上部に状態（認識中／再接続中／一時停止中）と経過時間
- 「文字起こし」と「メモ」をタブで切り替え（画面が広い端末では左右2カラム）
- 確定した文はその場でタップして修正でき、修正は自動保存されます
- メモの時刻をタップすると、対応する発言までスクロールします

## Androidでの使い方

1. スマホのChromeで、公開したURL（GitHub Pages など **https:// のURL**）を開きます。
2. メニューから「**ホーム画面に追加**」を選ぶと、アプリのように全画面で起動します。
3. 「新規セッション」→「録音開始」→ マイクの使用を**許可**します。
4. 話すと文字起こしが流れます。気づいたことは「メモ」タブから種別を選んで追加します。
5. 「終了して保存」で、音声・文字起こし・メモがまとめて端末内に保存されます。

> **マイクは https:// か localhost でしか使えません。** `file://` で直接開いた場合、録音も音声認識も動きません。

### 動作条件

| 項目 | 条件 |
| --- | --- |
| 推奨ブラウザ | Android Chrome（音声認識は Web Speech API を使用） |
| 必須 | HTTPS または localhost、マイクの許可 |
| 音声認識が使えない場合 | 「＋ 文章を追加」で手入力すれば、メモ・検索・書き出しはすべて使えます |
| オフライン | Service Worker により、一度開けば圏外でも起動します（認識は通信が必要な場合があります） |

## ローカルで動かす

`file://` では動きません。簡易サーバーを立てて開いてください。

```bash
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000` を開きます。

### テスト

Node.js がある場合:

```bash
node --test test/*.test.js
```

Node.js がない場合は、サーバーを立てて `http://localhost:8000/test/browser.html` を開くと、
同じテストファイルがブラウザ上で実行されます（`node:test` / `node:assert` はimport mapで差し替えています）。

### アイコンの作り直し

```bash
python3 tools/make_icons.py
```

## GitHubでの管理方針

提案書 5.2 のとおり、**GitHubには開発ファイルだけを置き、利用データは端末内に留めます。**

| 保存先 | 保存するもの | 保存しないもの |
| --- | --- | --- |
| GitHub リポジトリ | HTML / CSS / JS、テスト、CI設定、README、設計資料 | 録音音声、文字起こし本文、個人メモ、APIキー |
| GitHub Actions | ビルド・テスト結果、Pagesの成果物 | ユーザーデータ、秘密情報 |
| GitHub Pages | 動作確認済みのアプリ本体（静的ファイル） | 日常利用で生成される記録データ |
| Android端末（ブラウザ内） | 音声、文字起こし、修正後テキスト、複数メモ | — |

- リポジトリは **Private** で作成します。
- `main` を安定版、`feature/*` を開発用とし、変更は Pull Request で確認します。
- `.gitignore` で音声ファイル・バックアップJSON・秘密情報を除外しています。
- CI（`.github/workflows/ci.yml`）は、テストに加えて**音声ファイルや秘密情報がコミットされていないか**も検査します。

### 公開（GitHub Pages）

`.github/workflows/deploy-pages.yml` が `main` への push で自動デプロイします。

1. リポジトリの **Settings → Pages → Build and deployment → Source** を「**GitHub Actions**」に設定
2. `main` に push すると、`https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます

> **Privateリポジトリで Pages を使うには GitHub Pro / Team 以上のプランが必要です。**
> 無料プランのままにする場合は、次のいずれかを選びます。
> - リポジトリはPrivateのまま、公開用に別のホスティング（Cloudflare Pages / Netlify / Vercel の無料枠）へデプロイする
> - 自宅のPCでサーバーを立て、同じWi-Fi内のスマホから開く（この場合はhttpsでないためマイクが使えません）
> - リポジトリをPublicにする（**記録データはリポジトリに入らないため、公開してもデータ漏えいにはなりません**）

## 構成

```
kioku/
├── index.html              画面の入れ物（SPA）
├── manifest.webmanifest    ホーム画面に追加するための定義
├── sw.js                   オフライン用 Service Worker
├── css/styles.css          墨と紙のテーマ（ライト／ダーク対応）
├── js/
│   ├── main.js             起動とハッシュルーティング
│   ├── store.js            状態管理と保存（画面はここ経由でのみデータを触る）
│   ├── db.js               IndexedDB（セッションと音声を別ストアに保存）
│   ├── speech.js           Web Speech API（自動再開つき）
│   ├── recorder.js         MediaRecorder と画面消灯防止
│   ├── settings.js         設定（localStorage）
│   ├── ui.js               DOMヘルパー、ダイアログ、トースト
│   ├── lib/                DOM非依存の純粋関数（テスト対象）
│   │   ├── model.js        データモデル
│   │   ├── search.js       検索・絞り込み・並び替え
│   │   ├── export.js       テキスト／Markdown／CSV／JSON
│   │   ├── time.js         時刻整形
│   │   └── stopwatch.js    一時停止を含む経過時間
│   └── views/              ダッシュボード／記録／詳細／設定
├── test/                   ユニットテスト（Node・ブラウザ両対応）
├── tools/make_icons.py     アイコン生成
└── docs/                   設計資料
```

## プライバシーと制約

- 文字起こし・メモ・音声は**この端末のブラウザ内（IndexedDB）だけ**に保存され、サーバーへは送信されません。
- ただし、**ブラウザの音声認識は端末やブラウザによって音声を外部の認識サービスへ送信します。** 機密性の高い内容を扱う前に、お使いのブラウザの仕様を確認してください。
- ブラウザの「サイトデータを削除」を実行すると記録も消えます。大事な記録は設定画面から定期的にJSONバックアップを取ってください。
- ブラウザ版は画面を離れると認識が止まることがあります。長時間の常時録音が必要になった場合は、提案書のとおりKotlin＋Jetpack Composeのネイティブアプリ（Foreground Service）へ移行します。データモデルはそのまま流用できます。
