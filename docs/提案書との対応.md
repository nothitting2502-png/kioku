# 提案書との対応

『リアルタイム文字起こし・複数メモ管理アプリ 提案書 Ver.0.1』の各項目を、この実装がどう満たしているかの一覧です。

## 方針の変更点（重要）

提案書はAndroidネイティブ（Kotlin＋Jetpack Compose）を推奨構成としていましたが、
**ブラウザで使えること**を優先し、Androidの**Chromeで動くPWA**として実装しました。

| 提案書の構成 | この実装 | 理由 |
| --- | --- | --- |
| Kotlin / Jetpack Compose | HTML / CSS / JavaScript（ビルド不要） | インストールなしで試せる。ホーム画面に追加すればアプリのように使える |
| MediaRecorder＋Foreground Service | MediaRecorder＋Wake Lock | ブラウザにForeground Serviceがないため、画面消灯を防いで代替する |
| SpeechRecognizer | Web Speech API（自動再開つき） | 同じく短いセグメントを連続処理する設計 |
| Room＋アプリ専用ストレージ | IndexedDB（sessions / audio） | 端末内保存という性質は同じ |
| 共有Intent | Web Share API＋ダウンロード | Androidの共有シートがそのまま開く |

**制約**: ブラウザは画面を離れると認識が止まることがあります。画面オフ中の常時録音が必要になった場合は、
提案書どおりネイティブアプリへ移行します（データモデルはそのまま流用できます）。

## 6. 非機能要件・セキュリティ

| 項目 | 提案書のMVP目標 | 実装 |
| --- | --- | --- |
| 表示遅延 | 発話から表示までの遅延を小さくする | 途中結果をそのまま表示し、確定分のみ保存 |
| 保存の信頼性 | 終了操作後にセッションとメモが失われない | 確定ごとに保存、離脱時は `beforeunload` で確認して書き出し、一時停止・終了で確実に書き込み |
| データ管理 | 保存先・削除・書き出しを自分で操作できる | 設定画面にバックアップ／取り込み／保存期間／全削除 |
| 個人情報 | 外部APIへ送る音声の範囲を明示できる | 設定画面のプライバシー欄に、ブラウザの認識が外部送信し得ることを明記 |
| 障害対応 | 認識停止や通信エラーを画面で把握できる | 状態表示（認識中／再接続中／認識オフ）、原因別のバナーと「もう一度試す」、自動再開（指数バックオフ）、無反応を9秒で検知 |

## 9. リスクと対策

| リスク | 実装での対策 |
| --- | --- |
| 音声認識が長時間で途切れる | `onend` で自動再開。途中結果が残っていれば確定として保存し、取りこぼさない |
| **端末が録音と文字起こしを同時に使えない**（Androidで実際に発生） | 検知したら録音を手放して音声を保存し、文字起こしを優先。判定は端末ごとに記憶し、設定から戻せる |
| 端末や認識サービスで精度が違う | 全セグメントをその場でタップ修正でき、`edited` として区別。手入力の追加も可能 |
| 通信が不安定な環境で記録が途切れる | 確定ごとの保存、再接続表示、エラーバナー、Service Workerでアプリ本体はオフラインでも起動 |
| 個人情報・機密情報を含む | 端末内保存が基本。外部送信の可能性を設定画面で明示 |
| GitHubへ個人データを誤登録する | Private運用、`.gitignore`、CIでの混入検査（[GitHub運用.md](GitHub運用.md)） |
| 機能を広げすぎる | Must/Should のみ実装し、話者分離・AI要約は第2段階へ |

| 確認事項 | 現在の既定値 |

### 実機で分かったこと

Androidの実機では、録音はできるのに文字起こしだけが動かない事象が出た。原因は2つとも実装側の問題だった。

1. `SpeechRecognition.start()` を `await`（DB書き込みとマイク許可）のあとに呼んでいたため、ユーザー操作の権限コンテキストが切れて拒否されていた → タップ直後に同期で開始するよう修正
2. `MediaRecorder` が先にマイクを掴み、Androidの音声認識サービスが音声を取れなかった → 認識を先に始め、競合を検知したら録音を手放す
3. 認識が終了するたびに「途中結果」を新しい行として保存していたため、同じ文が何十行も積み上がった。Androidは話している間ずっと**そこまでの累積文**を返し続け、さらに `continuous` が効かず認識を何度も終了させるため、1秒ごとに同じ文が増えていく → 直前の行を伸ばすのか新しい行にするのかを [`js/lib/transcript.js`](../js/lib/transcript.js) の `decideCommit()` で判断し、Androidでは `continuous = false`（発話の切れ目で確定させる）に切り替えた

いずれもPCのChromeでは再現しないため、実機確認が不可欠だった。
3件目は偽の `SpeechRecognition` で実機のふるまいを再現する自動テスト（`test/speech.test.js`）を用意し、マイクなしでも検証できるようにしてある。
以前の版で積み上がってしまった記録は、起動時に一度だけ自動で畳んで直す（`store.repairDuplicateSegments()`）。
